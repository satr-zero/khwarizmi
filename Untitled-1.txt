class="detail-container detail-body-main"><div class="detail-tabs-content"><section class="tab-content detail-tab-readme-content -active markdown-body"><h1 id="webview_flutter_windows" class="hash-header">webview_flutter_windows <a href="#webview_flutter_windows" class="hash-link">#</a></h1>
<p><a href="https://pub.dev/packages/webview_flutter_windows"><img src="https://external-images.pub.dev/6LSn7C0YXNuUsDibBHCDTsqQONFVY2f%2F4sreRH0dyr0%3D/1788912000000/https%3A%2F%2Fimg.shields.io%2Fpub%2Fv%2Fwebview_flutter_windows.svg" alt="pub package"></a>
<a href="https://github.com/omar-hanafy/webview_flutter_windows/actions/workflows/ci.yml" rel="ugc"><img src="https://external-images.pub.dev/HaZYsoVRQljggZ3wGKoljTvMZUBLBKY0mqjBwoc6nsg%3D/1788912000000/https%3A%2F%2Fgithub.com%2Fomar-hanafy%2Fwebview_flutter_windows%2Factions%2Fworkflows%2Fci.yml%2Fbadge.svg" alt="CI"></a></p>
<p>A WebView for Flutter on Windows, powered by
<a href="https://learn.microsoft.com/en-us/microsoft-edge/webview2/" rel="ugc">Microsoft Edge WebView2</a>.
The browser is rendered off-screen and composited into your widget tree as a
regular Flutter <code>Texture</code>, so it behaves like any other widget: no airspace
issues, and transforms, opacity, and widgets painted on top all just work.</p>
<blockquote>
<p><strong>Fork notice:</strong> this is a maintained fork of
<a href="https://github.com/jnschulze/flutter-webview-windows" rel="ugc">jnschulze/flutter-webview-windows</a>.
It is not affiliated with the Flutter team's <code>webview_flutter</code> packages and
keeps the controller/widget API from <code>webview_windows</code>.
On top of upstream <code>0.4.0</code> it fixes the
<a href="https://github.com/jnschulze/flutter-webview-windows/issues/230" rel="ugc">window focus loss issue (#230)</a>,
hardens the native COM and channel layers, modernizes the toolchain
(WebView2 SDK <code>1.0.3967.48</code>, WIL <code>1.0.260126.7</code>, C++23), and ships a real
test suite. Coming from upstream? Read the
<a href="https://github.com/omar-hanafy/webview_flutter_windows/blob/main/migration_guide.md" rel="ugc">migration guide</a>.</p>
</blockquote>
<p><img src="https://external-images.pub.dev/O0oui2IR%2Fh0sNyFcmdjS3G%2BtPXQQ3d4ci9NOVp%2FQW%2FM%3D/1788912000000/https%3A%2F%2Fuser-images.githubusercontent.com%2F720469%2F116823636-d8b9fe00-ab85-11eb-9f91-b7bc819615ed.png" alt="Example app"></p>
<h2 id="ai-coding-assistant-support" class="hash-header">AI coding-assistant support <a href="#ai-coding-assistant-support" class="hash-link">#</a></h2>
<p>This repository ships an <strong>agent plugin</strong> for
<a href="https://code.claude.com/docs/en/discover-plugins" rel="ugc">Claude Code</a> and
<a href="https://learn.chatgpt.com/codex" rel="ugc">OpenAI Codex</a> with five package-specific
skills: integrating a webview, the Dart/JavaScript bridge and local content,
troubleshooting, writing channel-mocked tests, and migrating from
<code>webview_windows</code> 0.x. This is tooling for coding agents, not a runtime
feature of the Dart package, and it installs from this repository (it is not
part of the pub.dev archive).</p>
<p>Claude Code (CLI and desktop app) - inside a session:</p>
<pre><code class="language-text">/plugin marketplace add omar-hanafy/webview_flutter_windows
/plugin install webview-flutter-windows@webview-flutter-windows
</code></pre>
<p>then run <code>/reload-plugins</code> (or start a new session).</p>
<p>OpenAI Codex (CLI; installed plugins also surface in the ChatGPT desktop
app, not the IDE extension) - from a terminal:</p>
<pre><code class="language-sh">codex plugin marketplace add omar-hanafy/webview_flutter_windows
codex plugin add webview-flutter-windows@webview-flutter-windows
</code></pre>
<p>then start a new Codex session.</p>
<p>Example prompts: "Migrate this app from webview_windows to
webview_flutter_windows" or "The webview is blank and typing goes to the
wrong place, debug it". Skills also work explicitly:
<code>/webview-flutter-windows:integrate-webview-windows</code> in Claude Code,
<code>$integrate-webview-windows</code> in Codex.</p>
<p>The plugin is instructions-only: skills and reference files, no hooks, no
MCP servers, no executables, no network access. Its version tracks the
package release it shipped with, and the skills document the 1.x API
(<code>setDefaultContextMenusEnabled</code> needs <code>&gt;=1.1.0</code>). Full skill list,
updating, uninstalling, validation, and maintainer notes:
<a href="https://github.com/omar-hanafy/webview_flutter_windows/blob/main/docs/agent-plugin.md" rel="ugc">docs/agent-plugin.md</a>.</p>
<h2 id="features" class="hash-header">Features <a href="#features" class="hash-link">#</a></h2>
<ul>
<li><strong>Seamless composition.</strong> Web content renders into a Flutter <code>Texture</code>
inside your widget tree, not a native window floating above it.</li>
<li><strong>Keyboard focus that works.</strong> Clicking the webview does not deactivate
your window, clicking back on Flutter UI restores Flutter's keyboard
handling instantly, and <code>Tab</code> traversal leaves the page cleanly.</li>
<li><strong>Typed broadcast event streams</strong> for URL, loading state, document title,
navigation history, security state, full-screen elements, downloads, load
errors, web messages, and native focus.</li>
<li><strong>Two-way JavaScript bridge</strong>: execute scripts, register
on-document-created scripts, and exchange JSON messages with the page.</li>
<li><strong>Browser control</strong>: full cookie management (read, write, delete), cache,
user agent, zoom, background color, default context menus, popup policy,
virtual host mapping, suspend/resume, FPS limiting, and DevTools.</li>
<li><strong>Headless mode</strong>: drive a controller without a widget for background
pages, scraping, or pre-warming.</li>
<li><strong>Faithful input forwarding</strong>: mouse, high-precision trackpad scrolling,
and multi-touch.</li>
<li><strong>High-DPI aware</strong>, including per-view scale factors in multi-window apps.</li>
</ul>
<h2 id="requirements" class="hash-header">Requirements <a href="#requirements" class="hash-link">#</a></h2>
<p><strong>On your users' machines</strong></p>
<ul>
<li>Windows 10 1809 or newer (the off-screen compositor relies on
<code>Windows.Graphics.Capture</code>).</li>
<li>The <a href="https://developer.microsoft.com/en-us/microsoft-edge/webview2/" rel="ugc">WebView2 Runtime</a>.
It ships with Windows 11 and current Windows 10. To verify at startup, call
<code>WebviewController.getWebViewVersion()</code>: if it returns <code>null</code>, guide the
user to install the runtime.</li>
</ul>
<p><strong>On your development machine</strong></p>
<ul>
<li>Flutter 3.44+ / Dart 3.12+</li>
<li>Visual Studio 2022 with the <em>Desktop development with C++</em> workload</li>
<li>A Windows 10/11 SDK (installed with the workload by default)</li>
<li>Optional: <code>nuget.exe</code> in your <code>PATH</code> (the build downloads it automatically
if missing)</li>
</ul>

<h2 id="quick-start" class="hash-header">Quick start <a href="#quick-start" class="hash-link">#</a></h2>
<p>Create a <code>WebviewController</code>, initialize it, and hand it to a <code>Webview</code>
widget:</p>
<pre><code class="language-dart">import 'package:flutter/material.dart';
import 'package:webview_flutter_windows/webview_flutter_windows.dart';

class BrowserPane extends StatefulWidget {
  const BrowserPane({super.key});

  @override
  State&lt;BrowserPane&gt; createState() =&gt; _BrowserPaneState();
}

class _BrowserPaneState extends State&lt;BrowserPane&gt; {
  final _controller = WebviewController();

  @override
  void initState() {
    super.initState();
    _initWebview();
  }

  Future&lt;void&gt; _initWebview() async {
    await _controller.initialize();
    await _controller.setPopupWindowPolicy(WebviewPopupWindowPolicy.deny);
    await _controller.setDefaultContextMenusEnabled(true);
    await _controller.loadUrl('https://flutter.dev');
    if (mounted) {
      setState(() {});
    }
  }

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return _controller.value.isInitialized
        ? Webview(_controller)
        : const Center(child: CircularProgressIndicator());
  }
}
</code></pre>
<p><code>initialize()</code> completes with an error if the WebView2 Runtime is missing
(error code <code>environment_creation_failed</code>), so wrap it in a <code>try</code>/<code>catch</code> if
you want to show a friendly install prompt.</p>
<p>WebView2's default context menus are disabled by this package. Opt in before
starting the navigation that should use them, as shown above. A page may still
suppress its menu, and WebView2 applies a setting changed after navigation
starts to the next top-level navigation.</p>
<h2 id="listening-to-events" class="hash-header">Listening to events <a href="#listening-to-events" class="hash-link">#</a></h2>
<p>All controller streams are broadcast streams: attach as many listeners as you
like, but subscribe <em>before</em> triggering navigation, because events emitted
while nobody listens are dropped.</p>
<pre><code class="language-dart">controller.url.listen((url) =&gt; debugPrint('URL: $url'));
controller.loadingState.listen((state) =&gt; debugPrint('State: $state'));
controller.title.listen((title) =&gt; debugPrint('Title: $title'));
controller.historyChanged.listen((h) =&gt; debugPrint('canGoBack: ${h.canGoBack}'));
controller.onLoadError.listen((status) =&gt; debugPrint('Load error: $status'));
controller.onDownloadEvent.listen((e) =&gt; debugPrint('${e.kind}: ${e.url}'));
</code></pre>
<h2 id="talking-to-the-page" class="hash-header">Talking to the page <a href="#talking-to-the-page" class="hash-link">#</a></h2>
<p>Execute JavaScript and get its (JSON-decoded) result, or inject scripts that
run before any page script:</p>
<pre><code class="language-dart">final title = await controller.executeScript('document.title');

final scriptId = await controller.addScriptToExecuteOnDocumentCreated(
  'window.myAppReady = true;',
);
</code></pre>
<p>Exchange structured messages with the page:</p>
<pre><code class="language-dart">// Dart -&gt; page
await controller.postWebMessage('{"command": "ping"}');

// page -&gt; Dart
controller.webMessage.listen((message) {
  debugPrint('Page says: $message'); // already JSON-decoded
});
</code></pre>
<p>And on the JavaScript side:</p>
<pre><code class="language-js">window.chrome.webview.addEventListener('message', (e) =&gt; {
  console.log(e.data); // {command: 'ping'}
});
window.chrome.webview.postMessage({command: 'pong'});
</code></pre>
<h2 id="cookies" class="hash-header">Cookies <a href="#cookies" class="hash-link">#</a></h2>
<p>Read, write, and delete cookies through the WebView2 cookie store - useful
for extracting a session token after a login flow or seeding one before it:</p>
<pre><code class="language-dart">final cookies = await controller.getCookies('https://example.com');
final session = cookies.firstWhere((c) =&gt; c.name == 'session');

await controller.setCookie(WebviewCookie(
  name: 'theme',
  value: 'dark',
  domain: '.example.com',
  expires: DateTime.now().add(const Duration(days: 30)),
  isSecure: true,
  sameSite: WebviewCookieSameSite.strict,
));

await controller.deleteCookies('theme', uri: 'https://example.com');
await controller.clearCookies(); // everything
</code></pre>
<p>Omit <code>expires</code> to create a session cookie; pass an empty <code>uri</code> to
<code>getCookies</code> to list every cookie of the profile.</p>
<h2 id="headless-usage" class="hash-header">Headless usage <a href="#headless-usage" class="hash-link">#</a></h2>
<p>A controller works without a <code>Webview</code> widget: initialize it, give the
invisible page real bounds with <code>setSize</code> (pages do not perform layout until
they have nonzero bounds), and drive it through the normal API - load pages,
run scripts, exchange messages, read cookies. Nothing is rendered and no
frames are captured:</p>
<pre><code class="language-dart">final background = WebviewController();
await background.initialize();
await background.setSize(const Size(1280, 720));
await background.loadUrl('https://example.com/login');
// ... executeScript, webMessage, getCookies ...
await background.dispose();
</code></pre>
<h2 id="permission-requests" class="hash-header">Permission requests <a href="#permission-requests" class="hash-link">#</a></h2>
<p>Web content can request browser permissions (camera, microphone, geolocation,
clipboard, notifications). Decide per request via the <code>Webview</code> widget:</p>
<pre><code class="language-dart">Webview(
  controller,
  permissionRequested: (url, kind, isUserInitiated) async {
    final allowed = await askTheUser(url, kind);
    return allowed
        ? WebviewPermissionDecision.allow
        : WebviewPermissionDecision.deny;
  },
)
</code></pre>
<p>Return <code>WebviewPermissionDecision.none</code> to defer to the WebView2 default.</p>
<h2 id="keyboard-focus" class="hash-header">Keyboard focus <a href="#keyboard-focus" class="hash-link">#</a></h2>
<p>Clicking into the webview gives the page real Win32 keyboard focus; clicking
any Flutter widget hands focus back automatically. On top of that, one
invariant is enforced in both directions: <strong>while a Flutter text input owns
Flutter focus, no webview keeps native keyboard focus.</strong> If a dialog's
<code>TextField</code> gains focus while the page has the keyboard, focus is handed
back; if anything - <code>focus()</code>, page script, a stale refocus path in app
code - grabs native focus while a text input is focused, the grab is
reverted immediately. Typing can never silently land in the page. To move
focus into the page programmatically, unfocus the text input first. You
normally do not have to manage any of this. For programmatic control:</p>
<pre><code class="language-dart">await controller.focus();               // move keyboard focus into the page
await WebviewController.releaseFocus(); // hand it back to Flutter

controller.onFocusChanged.listen((focused) =&gt; debugPrint('Page focus: $focused'));
final focused = controller.hasNativeFocus;
</code></pre>
<h2 id="configuring-the-browser-environment" class="hash-header">Configuring the browser environment <a href="#configuring-the-browser-environment" class="hash-link">#</a></h2>
<p>The WebView2 environment is shared by all controllers and is created lazily
on the first <code>initialize()</code>. To customize it (user data directory, browser
executable, Chromium command line flags), configure it once <em>before</em> creating
any controller:</p>
<pre><code class="language-dart">await WebviewController.initializeEnvironment(
  userDataPath: r'C:\path\to\profile',
  additionalArguments: '--show-fps-counter',
);
</code></pre>
<p>The environment's lifecycle is reference counted: it is released when the
last controller is disposed. That means <code>initializeEnvironment</code> can be
called again - for example with a different <code>userDataPath</code> - once all
controllers are gone; it only throws a <code>PlatformException</code> while controllers
are alive.</p>
<h2 id="example-app-and-tests" class="hash-header">Example app and tests <a href="#example-app-and-tests" class="hash-link">#</a></h2>
<p>A complete example (URL bar, loading indicator, DevTools, permission prompts)
lives in <a href="https://github.com/omar-hanafy/webview_flutter_windows/blob/main/example" rel="ugc"><code>example/</code></a>: <code>cd example &amp;&amp; flutter run -d windows</code>.</p>
<p>The repository also ships:</p>
<ul>
<li>
<p>a Dart test suite (<code>flutter test</code>) covering the channel contract of every
controller method, the controller lifecycle, all events, and input/focus
forwarding,</p>
</li>
<li>
<p>native C++ unit tests (GoogleTest), run from the repository root:</p>
<pre><code class="language-sh">cmake -S windows/test -B build/native_tests
cmake --build build/native_tests --config Release
ctest --test-dir build/native_tests -C Release --output-on-failure
</code></pre>
</li>
<li>
<p>a real-input integration test for the focus behavior
(<code>example/integration_test/focus_test.dart</code>), which needs an interactive
Windows session.</p>
</li>
</ul>
<p>Tip for your own widget tests: when driving a <code>WebviewController</code> under
<code>testWidgets</code>, wrap <code>initialize()</code> and <code>dispose()</code> in <code>tester.runAsync(...)</code>.
Test bodies run in a fake-async zone where platform channel futures are not
driven, so awaiting them directly hangs the test.</p>
<h2 id="limitations" class="hash-header">Limitations <a href="#limitations" class="hash-link">#</a></h2>
<p>WebView2 has no official off-screen rendering API yet
(<a href="https://github.com/MicrosoftEdge/WebView2Feedback/issues/20" rel="ugc">WebView2Feedback#20</a>,
<a href="https://github.com/MicrosoftEdge/WebView2Feedback/issues/526" rel="ugc">#526</a>,
<a href="https://github.com/MicrosoftEdge/WebView2Feedback/issues/547" rel="ugc">#547</a>).
This plugin obtains frames through <code>Windows.Graphics.Capture</code>, which is why
Windows versions older than Windows 10 1809 are not supported.</p>
<h2 id="troubleshooting" class="hash-header">Troubleshooting <a href="#troubleshooting" class="hash-link">#</a></h2>
<ul>
<li><strong><code>initialize()</code> fails with <code>environment_creation_failed</code></strong>: the WebView2
Runtime is missing. Check <code>WebviewController.getWebViewVersion()</code> and point
the user to the <a href="https://developer.microsoft.com/en-us/microsoft-edge/webview2/" rel="ugc">runtime installer</a>.</li>
<li><strong>The build cannot download NuGet</strong>: install
<a href="https://www.nuget.org/downloads" rel="ugc">nuget.exe</a> manually and add it to <code>PATH</code>.</li>
<li><strong>Keyboard input stays in the page after clicking it</strong>: that is by design;
click any Flutter widget or call <code>WebviewController.releaseFocus()</code> to
return focus to Flutter.</li>
</ul>
<h2 id="migrating-from-upstream-04x" class="hash-header">Migrating from upstream 0.4.x <a href="#migrating-from-upstream-04x" class="hash-link">#</a></h2>
<p>Version 1.0.0 contains breaking changes (SDK floors, broadcast streams,
<code>WebErrorStatus</code> renames, stricter lifecycle errors). The
<a href="https://github.com/omar-hanafy/webview_flutter_windows/blob/main/migration_guide.md" rel="ugc">migration guide</a>
walks through every one of them, including the focus workarounds you can now
delete.</p>
